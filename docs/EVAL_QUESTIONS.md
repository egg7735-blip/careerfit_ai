# EVAL_QUESTIONS.md — CareerFit AI 자기 평가 질문



## 이 질문들에 스스로 답할 수 있어야 최종 발표와 면접에 나설 수 있다.



## 프로젝트 전체

- 이 서비스가 해결하는 문제는 무엇인가?
    취업을 준비하며 무엇을 준비해야 하는 지, 맞는 기술이 무엇일지 등을 자신의 학과, 역량에 맞게 알려주는 것

- RAG를 사용하지 않으면 어떤 문제가 생기는가?
    AI가 데이터를 참고하지 못하기 때문에 부정확한 답변을 할 수 있습니다.

- 가장 어려웠던 구현은 무엇이고, 어떻게 해결했는가?
    backend를 render로 외부 배포하는 부분이 제일 어려웠습니다. 깃허브에 커밋을 하지 않아서 오류가 발생했고 다시 커밋을 하여 해결하였습니다.


## 데이터 관련

- 왜 이 데이터를 선택했는가?
    실제 취업 공고를 기반으로 사용자의 역량을 분석하기 위해 채용 공고 데이터를 선택했습니다.

- 데이터의 어떤 부분이 신뢰할 수 없을 수 있는가?
    채용 공고는 시간이 지나면 마감되거나 요구 기술이 변경될 수 있어 최신성이 떨어질 수 있습니다.

- SQLite와 ChromaDB에 같은 데이터를 저장하는 이유는 무엇인가?
    SQLite는 조건 검색과 구조화된 데이터를 저장하고, ChromaDB는 의미 기반(RAG) 검색을 담당하기 때문입니다.

- 결측치와 중복을 어떻게 처리했는가?
    Pandas를 이용해 결측치는 제거하거나 기본값으로 처리하고, 중복 공고는 제거했습니다.


## RAG 관련

- RAG 구조에서 ChromaDB는 어떤 역할을 하는가?
    ChromaDB는 질문과 의미가 비슷한 공고를 찾는 레시피 북 역할을 합니다.

- n_results 값을 높이면 어떤 트레이드오프가 생기는가?
    더 많은 정보를 참고할 수 있지만, 관련성이 낮은 공고가 포함되어 응답 속도가 느려질 수 있습니다.

- 검색 결과 품질을 어떻게 검증했는가?
    다양한 질문으로 검색을 수행하고, 반환된 공고가 질문과 관련 있는지 직접 확인했습니다.

- Hallucination이 무엇이며, RAG가 이를 어떻게 줄이는가?
    Hallucination은 AI가 사실이 아닌 내용을 만들어내는 현상이며, RAG는 실제 검색된 공고를 근거로 답변하도록 하여 이를 줄입니다.

## API 관련

- /analyze 엔드포인트가 POST를 사용하는 이유는 무엇인가?
    사용자의 입력 데이터를 Request Body로 전달하기 때문에 POST를 사용했습니다.

- 응답 JSON에 sources를 포함시킨 이유는 무엇인가?
    AI가 어떤 공고를 근거로 답했는지 사용자에게 보여주기 위해 포함했습니다.

- /health 엔드포인트가 왜 필요한가?
    서버가 정상적으로 실행 중인지 확인하기 위한 상태 점검용입니다.



## 보안 관련

- .env 파일을 GitHub에 올리면 어떤 일이 생기는가?
    API Key 같은 민감한 정보가 공개되어 악용될 수 있습니다.

- .env와 .env.example의 차이는 무엇인가?
    .env는 실제 비밀 정보를 담고, .env.example은 변수 이름만 제공하는 예시 파일입니다.


## Docker 관련

- Docker를 사용하는 이유는 무엇인가?
    개발 환경과 실행 환경을 동일하게 만들어 어디서나 같은 방식으로 실행하기 위해 사용합니다.

- Dockerfile에서 EXPOSE와 CMD의 역할은 무엇인가?
    EXPOSE는 사용할 포트를 알리고, CMD는 컨테이너가 시작될 때 실행할 명령을 지정합니다.
